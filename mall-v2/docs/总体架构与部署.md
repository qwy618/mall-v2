## 1. 系统总览

单体多模块后端 + 两个独立前端应用，全部通过 Nginx 反向代理对外暴露；中间件以 Docker 方式独立部署。

```
                         ┌─────────────────────────────────────────────┐
   浏览器 (C 端用户)      │              Nginx (反向代理)                │
   浏览/下单/支付 ───────▶│   :8088  portal-web(dist)                    │
                         │      /api/  ──────────────▶ :8081 portal     │
                         └─────────────────────────────────────────────┘
                         ┌─────────────────────────────────────────────┐
   浏览器 (运营/管理员)   │   :9080  mall-admin-v2(dist)                 │
   商品/订单/权限 ───────▶│      /api/  ──────────────▶ :8080 admin      │
                         │      /ws/   ──────────────▶ :8080 WebSocket  │
                         └─────────────────────────────────────────────┘

   portal(:8081) ──┐   admin(:8080) ──┐
                   │                  │
        ┌──────────▼──────────────────▼──────────┐
        │   MySQL mall_v2 (3306)  ·  阿里云 OSS    │
        │   Redis (发布订阅/缓存)  ·  RabbitMQ     │
        │   Elasticsearch (商品搜索)               │
        └──────────────────────────────────────────┘
```

> 注：当前后端为**单体多模块**（parent + common + mbg + admin + portal），**无注册中心 / 无 RPC**。portal 与 admin 是两个独立 Spring Boot 应用，共享 `mall-mbg` 生成的实体与 `mall-common` 公共组件，但各自连同一库 `mall_v2`、各自鉴权。

## 6. 鉴权体系

- **JWT**：登录发 token，`JwtAuthenticationTokenFilter` 校验；C 端 `memberId` 统一取 `MemberAuth.memberId()`。
- **RBAC（后台）**：`ums_role.menu_ids` 决定菜单/接口权限；`canAccess` 守卫。
- **接口级鉴权**：`MenuPermissionInterceptor` + `WebMvcConfig` 按 `menuIds` 拦业务接口（`/brand→Brand`、`/product|/sku→Product`、`/comment→Comment`、`/admin/dashboard/**→Dashboard` 等），排除 login/info/静态/error/swagger；`/role/**` 与管理员管理保持 `hasRole("admin")`。
- **放行项**：`/ws/**`（WebSocket 握手）、login、info、静态资源、error、swagger。

## 7. 核心业务流程

### 7.1 下单 → 支付（Mock）→ 超时取消
1. C 端 `POST /order/create`：校验库存（防超卖）、算价、`orderSn` 唯一、**发 RabbitMQ 延迟消息（30min TTL）**。
2. `POST /order/pay`：当前为 **Mock 支付**（写库 `status=1` + 发 Redis `mall:order:paid` 频道消息）。真实支付已暂缓。
3. 30min 未付 → `OrderCancelListener.cancelExpiredBySystem()` 幂等取消（回补库存）。

### 7.2 商品搜索
- 主路径 **Elasticsearch**：`EsProductService.search()`；商品 CRUD 经 `ProductSyncListener` **实时同步**索引；`EsDataInitializer` 初始化灌库。
- 降级：ES 异常 / 无关键词时回退 DB `LIKE`（仅兜底，非主路径）。

### 7.3 新订单实时提醒（后台）
```
portal 支付 ──Redis PUBLISH(mall:order:paid)──▶ admin RedisMessageListenerContainer
        ──▶ OrderPaidSubscriber ──▶ WebSocket /ws/admin ──▶ 前端 ElNotification
        + speechSynthesis 朗读"你有新的用户订单，请及时发货" + 列表置顶高亮
```

## 9. 部署架构（Nginx 生产形态）

### 9.1 端口规划

| 端口 | 服务 | 说明 |
|---|---|---|
| 8088 | Nginx → C 端 | 静态 `portal-web/dist` + `/api/` 反代 8081 |
| 9080 | Nginx → 管理端 | 静态 `mall-admin-v2/dist` + `/api/` 反代 8080 + `/ws/` 反代 8080 |
| 8080 | mall-admin jar | 后台 API + WebSocket |
| 8081 | mall-portal jar | C 端 API |
| 80 | （被系统 PID4 占用，故改用 8088/9080） | — |

### 9.2 Nginx 关键配置（可用模板：`deploy/nginx.conf`，落地于 `C:/nginx/conf/mall.conf`）

```nginx
# C 端 :8088
server {
    listen 8088;
    root C:/Users/29154/Desktop/全栈项目/portal-web/dist;
    location ~* \.(js|css|png|...)$ { expires 7d; add_header Cache-Control "public"; }
    location /api/  { proxy_pass http://127.0.0.1:8081/; }   # 末尾 / 去掉 /api 前缀
    location /      { try_files $uri $uri/ /index.html; }     # SPA 兜底
}

# 管理端 :9080
server {
    listen 9080;
    root C:/Users/29154/Desktop/全栈项目/mall-admin-v2/dist;
    location /api/  { proxy_pass http://127.0.0.1:8080/; }
    location /ws/   {
        proxy_pass http://127.0.0.1:8080;        # ⚠ 末尾【不要】加 /，否则 /ws/admin→/admin 导致 401
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";    # WebSocket 握手必须
    }
    location /      { try_files $uri $uri/ /index.html; }
}
```

### 9.3 ⚠ 部署必踩坑（已踩过，记此避免复发）

1. **`/ws/` 反代尾斜杠**：`proxy_pass` 末尾带 `/` 会把 `/ws/admin` 改写成 `/admin`，后端 401、无提示音。正确写法 `proxy_pass http://127.0.0.1:8080;`（无尾斜杠）。改完 `nginx -s reload`。
2. **生产 `.env` 缺失 → 405**：前端生产构建必须存在 `.env`（`VITE_BASE_API=/api`）。缺失时 `import.meta.env.VITE_BASE_API` 为 `undefined`，API 丢 `/api` 前缀打到静态文件报 405。补 `.env` 后重新 `npm run build`。
3. **`npm run build` 清 dist 触发沙箱审批**：`npm run build` 会删 `dist/` 下 >50 文件，可能被安全策略拦截。绕过：先 `mv dist dist.old` 再 build；被拒时用 `npx vue-tsc --noEmit` + curl dev 模块(200) 验证。
4. **旧 jar 文件锁**：重新 `package` 前先 `taskkill` 旧后端进程，否则旧 jar 被占用导致打包失败。
5. **后端启动**：`java -jar <jar> --server.port=8080|8081`；后台起后用 curl 探活（**勿用 TaskOutput 探活，会杀进程**）。admin 登录 `admin/macro123`。

### 9.4 启动顺序

1. 起中间件（MySQL/Redis/RabbitMQ/ES，Docker）。
2. 后台起 `mall-admin.jar`(8080) 与 `mall-portal.jar`(8081)。
3. `nginx -s reload`（确保 `mall.conf` 已 include 且 WS 配置正确）。
4. 验证：curl 8080/8081 健康检查；浏览器开 8088（C 端）、9080（管理端）。

## 10.5 库存锁定释放（债务 5，2026-10-07）

**两计数器模型**：`stock` 实物库存、`lock_stock` 锁定库存（被待支付订单预占的量），
**可售库存 = `stock − lock_stock`** —— 一切「还有没有货」的判断都用可售。

统一口径收在 **`mall-service.SkuStockService`**（portal 与 admin 共用，跨端唯一实现）：

| 方法 | SQL（全部是「条件 UPDATE + 查 affected rows」） | 触发于 |
|---|---|---|
| `lock()` | `SET lock_stock = lock_stock + n` `WHERE id=? AND stock - lock_stock >= n` | 下单（含后台代客下单） |
| `consume()` | `SET stock = stock - n, lock_stock = lock_stock - n` `WHERE id=? AND lock_stock >= n` | 支付成功 |
| `release()` | `SET lock_stock = lock_stock - n` `WHERE id=? AND lock_stock >= n` | 取消 / 超时关单 |
| `restore()` | `SET stock = stock + n` `WHERE id=?` | 作废订单（已付款未发货） |

- 判据落在 SQL 内（不是「先查再改」），由 InnoDB 行锁保证原子 → 无超卖窗口。
- `lock_stock >= n` 是**释放的天然幂等守卫**（重复释放 affected=0，不会减成负数）；
  但「一次取消归还两次」要靠调用方的**原子状态流转**挡：`cancel`/`cancelExpiredBySystem`
  必须先原子改状态（`WHERE id=? AND status=0`，affected=0 直接返回），成功者才释放。
- **不变量**（任何时刻恒成立，巡检见 `docs/sql/016_sku_lock_stock.sql`）：
  `lock_stock >= 0` 且 `lock_stock <= stock`；且 `lock_stock` == 该 SKU 在待支付订单里的数量之和。
- 订单状态机补充：`0 待支付 → 1 已支付 → 2 已发货 → 3 已完成`，旁支 `4 已关闭(取消)`、`5 无效(作废)`。

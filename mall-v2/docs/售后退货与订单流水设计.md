# 售后退货（债务 14）+ 订单操作流水（债务 13）设计

> 联动债务 7：退款金额一律取 `order_item.real_amount`，杜绝"按原价退"的薅羊毛漏洞。
> 状态：设计稿（2026-10-01）。落盘范围：DDL / MBG 样板（已授权）+ 业务 service/controller（用户指示"接着做"一并落盘）。

## 一、两张新表

### 1. `order_return_apply`（售后退货申请单）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AUTO | 主键 |
| order_id | BIGINT | 关联订单 |
| order_sn | VARCHAR(64) | 冗余订单号 |
| member_id | BIGINT | 申请人（会员） |
| return_amount | DECIMAL(10,2) | **退款金额 = Σ(real_amount × 退数/行数)**，下单时已落库，不依赖券是否过期 |
| reason | VARCHAR(200) | 退货原因 |
| description | VARCHAR(500) | 说明 |
| proof_pics | VARCHAR(1000) | 凭证图 URL 数组（JSON） |
| return_items | TEXT | 退货明细 JSON：`[{orderItemId, skuId, productId, productName, productPic, quantity, realAmount}]` |
| status | TINYINT | 0待审核 1已同意 2已拒绝 3已收货(退款中) 4已完成 5已关闭 |
| handle_note | VARCHAR(500) | 处理备注 |
| handle_man | VARCHAR(64) | 处理人（管理员用户名） |
| company_address | VARCHAR(200) | 退货收货地址（管理端同意时填） |
| return_tracking_no | VARCHAR(64) | 会员回填的退货物流单号 |
| create_time | DATETIME | 默认 now |
| update_time | DATETIME | on update |

> 退货明细用 JSON 内联，避免再建子表（学习项目够用，查询走应用层）。如需严格关系建模，后续可拆 `order_return_item`。

| 字段 | 类型 | 说明 |

| operate_note | VARCHAR(500) | 备注（如发货公司+单号） |

## 二、退款金额算法（联动债务 7）

```
return_amount = Σ_item ( item.real_amount × returnQty / item.quantity )
守卫：return_amount ≤ order.payAmount（多行累加封顶，防超退）
```

- `real_amount` 在**下单时**已由 `OrderServiceImpl.allocateDiscount()` 计算落库（债务 7）。
- 退款按"实付分摊"退，与券是否过期、是否满减无关——数学恒等，无漏洞。

## 三、退货状态机

```
申请(会员) status 0 待审核
   ├─ 管理端 同意 → 1 已同意（填退货地址 company_address）
   │     会员 回填物流单号(return_tracking_no)
   │     管理端 确认收货 → 3 已收货
   │           管理端 完成退款 → 4 已完成（标记退款完成；真实打款暂缓，支付为 Mock）
   ├─ 管理端 拒绝 → 2 已拒绝（流程结束）
   └─ 会员 撤销 / 超时 → 5 已关闭（可选，先不做自动关闭）
```

> 订单本身 `status` 不变（仍为 3 已完成），退货走独立申请单；退款完成不回滚订单状态，保持简单。

## 四、接口设计

### C 端（portal）`/return/**`（会员 JWT 鉴权，无菜单拦截）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/return/apply` | 申请退货：`{orderId, items:[{orderItemId, quantity}], reason, description, proofPics}`。校验：订单归属会员 + `status=3` 已完成；逐行算 `return_amount`；写申请单(0) + 流水(RETURN_APPLY) |
| GET | `/return/list` | 我的退货申请列表（按 member_id） |
| GET | `/return/detail/{id}` | 申请详情 |
| POST | `/return/shipBack/{id}` | 会员回填退货物流单号 `{returnTrackingNo}`（status 保持 1，仅补单号） |

### 管理端（admin）`/order/return/**`（继承 `/order/**`→`Order` 菜单权限，无需改菜单）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/order/return/list?status=` | 申请列表（按状态筛） |
| GET | `/order/return/{id}` | 详情 |
| POST | `/order/return/approve/{id}` | 同意：`{handleNote, companyAddress}` → status=1 + 流水(RETURN_APPROVE) |
| POST | `/order/return/reject/{id}` | 拒绝：`{handleNote}` → status=2 + 流水(RETURN_REJECT) |
| POST | `/order/return/receive/{id}` | 确认收货 → status=3 + 流水(RETURN_RECEIVE) |
| POST | `/order/return/complete/{id}` | 完成退款：`{handleNote}` → status=4 + 流水(RETURN_COMPLETE) |

## 五、订单操作流水（债务 13）埋点

在**现有订单状态变更处**补写 `order_operate_history`：
- portal：`createOrder`→CREATE、`pay`→PAY、`cancel`→CANCEL、`confirmReceived`→CONFIRM、退货申请→RETURN_APPLY
- admin：`ship`→SHIP、`complete`→CONFIRM(admin)、`cancel`→CANCEL、退货审核各节点→RETURN_*

操作人：`portal` 端记 `会员{memberId}`；`admin` 端从 `SecurityContextHolder` 取 `AdminUserDetails.getUsername()`。

## 八、验收标准

1. 前端用券下单 → 完成收货 → 申请退 1 件 → `order_return_apply.return_amount = 该行 real_amount × 1/qty`（非原价）
2. 管理端审核流：approve(填地址)→ 会员 shipBack(填单号)→ receive → complete，状态 0→1→3→4
3. `order_operate_history` 对应该订单有完整留痕（创建/支付/发货/确认/退货各节点）
4. 越权校验：会员不能退他人订单；非 completed 订单不能退

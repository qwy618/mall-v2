# 购物车快照 + 未登录合并 设计（债务 16 + 阶段5快照偏差）

> 版本：2026-10-02　｜　范围：`mall-portal` 购物车 + `portal-web` 结算/登录/购物车页
> 结论：① `cart_item` 落商品快照，商品下架后购物车项灰显保留；② 未登录加购写 localStorage 暂存车，登录后合并进会员购物车。
> 已落盘并 E2E 验证（直连 8081 与经 nginx 8088 各 15 项断言全绿）。

## 1. 背景

- 阶段5 设计结论要求购物车"存商品快照"，但实际 `cart_item` 只存 `member_id/sku_id/quantity/checked`，购物车页靠 JOIN `sku`/`product` 取名称/图片/价格。后果：商品下架或 SKU 删除后，购物车项**凭空消失**（原 `list` 里 `if (sku == null) continue`）。
- `cart_item` 无匿名购物车机制，未登录无法加购，且登录前后购物车不连贯。

## 2. 方案一：商品快照（债务16-快照偏差）

### 2.1 DB（DDL 011，`docs/sql/011_cart_snapshot.sql`，可重跑）
`cart_item` 加 6 列：
| 列 | 类型 | 说明 |
|---|---|---|
| `product_id` | bigint | 商品ID（快照） |
| `product_name` | varchar(200) | 商品名（快照，下架仍可读） |
| `sku_code` | varchar(100) | SKU 编码（快照） |
| `pic` | varchar(500) | 商品图（快照） |
| `sp_data` | varchar(500) | 规格 JSON（快照，展示用） |
| `price` | decimal(10,2) | 加入时快照单价（下架/缺货兜底展示） |

用存储过程按 `information_schema` 存在性守卫逐个 ADD，可重复执行。

### 2.2 后端
- `CartServiceImpl.add` / `merge`：插入新行时调用 `buildSnapshotItem()`，落 `productId/productName/skuCode/pic/spData/price`（来自 `sku` + `product`）。
- `CartServiceImpl.list` 在线判定：`sku != null && product != null && product.status == 1`（商品物理删除 → `product == null` → 失效）。
  - 在线：`price = sku.price`、`stock = sku.stock`（实时，下单以库为准）。
  - 失效：`price` 回退快照价、`stock = 0`、`offline = true`；名称/图片优先实时，缺失则回退快照。
- `CartItemVO` 新增 `productId / spData / offline`。

### 2.3 前端
- `views/cart/index.vue`：`offline` 项灰显（`opacity/grayscale`）、显示"已失效"标签、复选框与数量框禁用、默认不选中、不可结算；新增"清理失效商品"按钮。
- 购物车角标（`App.vue`）：未登录读 localStorage 暂存车数量，登录态变化后刷新。

## 3. 方案二：未登录合并（债务 16）

### 3.1 流程
1. 未登录用户点"加入购物车" → 前端写 `localStorage.guestCart`（`{skuId, quantity}`，同 sku 累加）。
2. 登录成功（`views/login/index.vue`）→ 调 `POST /cart/merge` 提交暂存车 → 清空 localStorage → 跳 `/cart` 展示合并结果。
3. 已登录用户加购仍走原 `POST /cart/add`。

### 3.2 后端
- 新增 `POST /cart/merge`：`@RequestBody List<CartMergeParam>`（`skuId + quantity`）。
- `CartServiceImpl.merge`：逐条校验，无效 SKU 静默跳过（不报错）；已存在则数量累加，不存在则 `buildSnapshotItem` 新插。
- 幂等性：依赖前端登录后清空 localStorage，故不会重复合并；同一 sku 在暂存车内前端已合并为一条。

## 4. 关键决策
- **快照不覆盖实时价**：`list` 在线时价格/库存仍取库实时值，快照仅作"下架兜底"，保证下单金额以库为准（与债务7退款口径一致）。
- **离线仍可结算吗**：不可。`offline` 项前端禁用勾选，结算只统计在线项。
- **合并放在登录成功处**而非路由守卫：登录是唯一可靠的"身份跃迁"点，且能立即给"登录后看到车里有东西"的反馈。

## 5. E2E（`scripts/e2e_cart_snapshot_merge.py`，15 项全绿）
- 快照：加购后 `cart_item` 六列落库；在线 `offline=false`、价格=库价、名称=商品名；商品 `status=0` 后 `offline=true`、名称/价格回退快照。
- 合并：同 SKU 合并数量累加（2+3=5）；无效 SKU 被跳过无新增；新 SKU 合并新增一行。
- 双通道：直连 8081 与经 nginx 8088 各跑一遍一致。

## 6. 边界 / 未完成
- 债务 17（购物车 Redis 缓存）仍 `待补`：当前仍直查 MySQL。
- 暂存车仅存 `skuId+quantity`，未存快照；合并后展示依赖会员购物车 `list` 的实时/快照逻辑，正确。
- 未做"多端同步"（不同浏览器暂存车不互通）——属 localStorage 方案固有限制，足够学习项目使用。

## 1. 业务规则（唯一口径）

| 规则 | 取值 | 说明 |
|---|---|---|
| 积分抵扣比例 | **100 积分 = 1 元** | `IntegrationService.POINTS_PER_YUAN` |
| 积分赠送时机 | **确认收货（交易完成）** | 而非支付后：避免"下单-支付-退款"刷分 |
| 赠送积分 | `floor(实付金额 × 等级积分倍率%)` | 倍率来自 `member_level.integration_rate` |
| 成长值增长 | `floor(实付金额)`，1 元 = 1 成长值 | 只增不减 |
| 等级判定 | 取 `growth_point <= 成长值` 的**最高档** | 由成长值反推，不手工改等级 |
| 等级权益 | ① 积分倍率 ② 会员折扣（整单） | 折扣写入 `orders.promotion_amount` |
| 抵扣上限 | `min(申请积分, 账户余额, 券后应付×100)` | 三重钳制，实付永不为负 |

### 四档等级（DDL 010 种子数据）

| id | 名称 | 成长值门槛 | 积分倍率 | 会员折扣 |
|---|---|---|---|---|
| 1 | 普通会员 | 0 | 100%（1 倍） | 无（100%） |
| 2 | 银卡会员 | 1000 | 120%（1.2 倍） | 99 折 |
| 3 | 金卡会员 | 5000 | 150%（1.5 倍） | 98 折 |
| 4 | 钻石会员 | 20000 | 200%（2 倍） | 95 折 |

## 2. 金额计算口径（下单时一次算定）

```
total_amount       = Σ sku.price × qty                     商品总额
promotion_amount   = total × (100 − level.discount_rate)%   会员折扣
coupon_amount      = min(券面额, 券适用商品小计)            优惠券
integration_amount = 使用积分 / 100                          积分抵扣
pay_amount         = total + freight − promotion − coupon − integration   （≥ 0）
```

**分摊到订单项**（债务 7 的延伸）：三类优惠各自按「本行原价小计 / 全单原价小计」比例分摊，
前 n−1 行四舍五入、尾行吸收余数，保证各类 Σ 分摊 == 该类整单优惠额：

```
order_item.promotion_amount / coupon_amount / integration_amount   ← 分摊结果
order_item.real_amount = 行原价小计 − 三项分摊之和                  ← 退款按此值
```

> 这是债务 7「防多退」的前置：退款金额严格取自 `real_amount`，与优惠叠加方式解耦。

## 3. 数据模型（DDL 010）

```
member                         member_level（等级配置，4 档种子）
+ level_id                     id / name / growth_point
+ integration                  integration_rate  积分倍率(%)
+ growth                       discount_rate     会员折扣(%)
+ history_integration          note / create_time

member_integration_history（积分流水）
id / member_id / order_id / order_sn
change_type   1下单赠送 2下单抵扣 3退货扣回 4管理员调整
change_count  正=获得 负=消耗
integration_after  变动后余额（对账）
operate_man / operate_note / create_time

orders
+ promotion_amount   会员折扣金额
+ use_integration    使用的积分数
+ integration_amount 积分抵扣金额
```

> `promotion_amount` / `integration_amount` 同时补上了**债务 6**（orders 缺这两列）。

## 5. 并发与幂等

| 位置 | 手段 | 防的问题 |
|---|---|---|
| 积分抵扣扣减 | `UPDATE member SET integration = integration − ? WHERE id = ? AND integration >= ?` | 并发超用扣成负数（affected=0 → 抛"积分不足"整单回滚） |
| 赠送积分/成长值 | `setSql("integration = integration + ?, growth = growth + ?")` 原子累加 | 并发订单互相覆盖 |
| 赠送只发生一次 | 确认收货改为 `UPDATE ... WHERE status = 2` 原子流转，`affected == 1` 才赠送 | 重复点击 / 并发重复确认 → 重复赠送 |
| 下单重复提交 | 复用债务 23 的一次性 Token | 同一次业务意图只落一单 |

> 与债务 23 的调用顺序：`claim`（第一行）→ 校验 → 算金额 → 建单 → 券核销 → **扣积分** → 分摊 → 插明细；
> 任一步抛异常 → 事务回滚，`finally` 回退令牌，用户可修正后重试。

## 6. C 端 UI

- **个人中心**：会员成长卡（可用积分 / 成长值 / 会员折扣 / 积分倍率）+ 等级进度条 + 「积分明细」入口；顶部徽标显示真实等级名（原为写死的 "PLUS 会员"）。

- **确认订单页**：会员折扣行 + 积分抵扣区（显示可用积分、本单最多可用、开关整单抵扣）+ 结算明细逐项列出。
- **订单详情页**：金额信息新增「会员折扣 / 积分抵扣（N 积分）」行。

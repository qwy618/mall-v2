# 优惠分摊到 order_item + 退款取数设计（债务 7）

> 状态：设计稿（2026-10-01）｜ 关联债务：7（高优）、6（部分已补）、14（售后，待做）
> 目标：下单时把整单优惠**按比例摊到每一行 `order_item`**，并把"该行实际实付"持久化；退款一律按实际实付退，杜绝薅羊毛。

---

## 1. 问题回顾

当前 `orders` 有整单优惠 `couponAmount`（及未来 `promotion_amount`/`integration_amount`/`discount_amount`），但 `order_item` 只存快照 `price`（原价）和 `quantity`，**没有"本行分摊了多少优惠、实际付了多少"**。一旦做退款（债务 14），若按 `price` 退就会多退，形成漏洞。

---

## 2. 字段设计（DDL）

在 `order_item` 上新增 4 列（金额统一 `DECIMAL(10,2)`，默认 0，避免 NULL 干扰求和）：

```sql
ALTER TABLE order_item
  ADD COLUMN coupon_amount      DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '本行分摊的优惠券金额',
  ADD COLUMN promotion_amount   DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '本行分摊的促销/满减金额',
  ADD COLUMN integration_amount DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '本行分摊的积分抵扣金额',
  ADD COLUMN real_amount        DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '本行实际实付 = price*qty - 各项分摊';
```

> 说明：当前系统**只实现了优惠券**（`orders.couponAmount`），所以落地时 `promotion_amount`/`integration_amount` 默认 0，框架预留。等债务 6 把整单 `promotion_amount`/`integration_amount`/`discount_amount` 字段补上后，分摊框架自动支持，无需改算法。
>
> `real_amount` = 本行原价小计 − 本行分摊的（coupon + promotion + integration + discount）。**运费不计入 `real_amount`**（运费是否退单独处理，见 §5）。

---

## 3. 分摊算法（下单时执行）

位置：`OrderServiceImpl.create()`，在算出整单 `couponAmount`（等）之后、插入 `order_item` 之前。

### 3.1 输入
- `items`：每个 `order_item` 的 `price`、`quantity` → 本行原价小计 `lineTotal_i = price_i × quantity_i`
- 整单优惠：`couponAmount`（及未来 `promotionAmount`/`integrationAmount`/`discountAmount`），均为 `BigDecimal`
- `sumLineTotal = Σ lineTotal_i`（不含运费）

### 3.2 核心逻辑（按比例 + 尾行吸收余数）

对**每一种**优惠类型 `D ∈ {coupon, promotion, integration, discount}` 分别分摊：

```
remaining = D.wholeOrderAmount          // 该类型整单优惠总额
allocatedSum = 0
for i in 0 .. n-1:
    if i == 最后一个商品行:
        itemAlloc = remaining - allocatedSum          // 尾行吸收四舍五入余数，保证 Σ == 整单额
    else:
        ratio     = lineTotal_i / sumLineTotal
        itemAlloc = round2(remaining * ratio)          // 两位小数 HALF_UP
        allocatedSum += itemAlloc
    item_i.D_amount += itemAlloc                       // 累加进对应列

// 每行实际实付
item_i.real_amount = lineTotal_i
                    - item_i.coupon_amount
                    - item_i.promotion_amount
                    - item_i.integration_amount
                    - item_i.discount_amount
```

### 3.3 精度与一致性要求（必须遵守）
- **全部用 `BigDecimal`，scale=2，`RoundingMode.HALF_UP`**，禁止用 `double/float` 算钱。
- **尾行吸收余数**：前 n-1 行四舍五入，最后一行用 `remaining - 已分配和`，确保 `Σ(item.D_amount) == D.wholeOrderAmount` 精确相等（避免 0.01 误差导致对账不平）。
- 兜底：若某行 `lineTotal_i` 为 0（异常），分摊给它 0，余数继续向后传递。
- 上限保护：单一优惠的分摊额不超过该行 `lineTotal_i`；若整单优惠 > `sumLineTotal`（理论上不该发生），按行封顶并记日志告警。

### 3.4 数值演练（满 200 减 100 券，买 A、B 各 1 件）

| 行 | lineTotal | coupon 分摊（比例 50%） | real_amount |
|---|---|---|---|
| A | 100 | 50.00 | 50.00 |
| B | 100 | 50.00 | 50.00 |
| 合计 | 200 | **100.00** | **100.00** |

→ `Σ coupon_amount = 100 = orders.couponAmount` ✅；`Σ real_amount = 100 = orders.payAmount − freight` ✅

三件不等额示例（券 10 元，A=100/B=33/C=67，sum=200）：
- A: 10×0.5=5.00；B: 10×0.165=1.65；C(尾行): 10−5−1.65=3.35 → Σ=10.00 ✅

## 4. 退款取数规则（债务 14 联动）

退款服务（未来新建）**只认 `real_amount`，绝不回退到 `price`**：

- **整行退**：退 `item.real_amount`
- **部分数量退**（退 `r` 件，`r ≤ quantity`）：退 `item.real_amount × r / quantity`（四舍五入），且 `r` 不得超过可退数量
- **多行合并退**：累加各行退款，`Σ 退款 ≤ orders.payAmount`（加守卫，超限拒绝）
- **运费**：默认不退；若业务要退运费，单独从 `orders.freightAmount` 取，不混入 `real_amount`

> 因为分摊在**下单时**已落库，退款无需重算、也不依赖券是否过期/变更，数据自洽。

---

## 5. 边界与注意事项

1. **无优惠场景**：`couponAmount=0` → 所有分摊列 0，`real_amount = lineTotal`，退款即按原价，行为不变。
2. **运费不参与分摊**：`real_amount` 不含运费；`orders.payAmount = Σ real_amount + freightAmount` 须恒成立（验收点）。
3. **MBG 再生**：新增列后需让 `OrderItem` 实体带这 4 个字段。MBG 全量再生会覆盖手写内容，建议**仅增量补字段**（手动加字段 + getter/setter，或单独跑针对 `order_item` 的 MBG）。按约定 DDL/MBG 样板可由 AI 落盘。
4. **前端**：订单详情/退款页展示"实付"用 `real_amount`，不要继续用 `price×qty` 当实付。

---

## 6. 验收标准

| # | 验收点 | 期望 |
|---|---|---|
| 1 | 带券下单后 `Σ order_item.coupon_amount` | 精确等于 `orders.couponAmount`（差 0.00） |
| 2 | `Σ order_item.real_amount + orders.freight_amount` | 精确等于 `orders.payAmount` |
| 3 | 退单行（有券） | 退回金额 == `real_amount`，**不是** `price×qty` |
| 4 | 三行不等额 + 券 10 元 | 各行分摊求和 == 10.00（尾行吸收余数生效） |
| 5 | 多行退款累加 | `Σ 退款 ≤ payAmount`，超限拒绝 |
